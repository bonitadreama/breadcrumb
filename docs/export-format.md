# JSON backup format v2

Envelope fields: `format: "personal-health-timeline"`, `formatVersion: 2`, `exportedAt`, `appVersion`, and arrays `profiles`, `preferences`, `eventTypes`, `observations`, `medicationSchedules`, `episodes`, `tags`, `photoAssets`. Legacy v1 files are upgraded in memory with an empty photo array before validation.

All historical definition revisions and extension data are included. Device navigation state is not included. Serialization preserves record IDs, UTC instants, IANA zones, uncertainty bounds, tags, and notes. `source` remains unchanged on restore because restore is not a new observation.

Observation edit history uses `extensions["breadcrumb.observation-history"] = { version: 1, entries: Observation[] }`. Entries are ordered oldest first, retain identity/creation time/type revision, and omit the history extension itself to avoid recursion. The current record has the latest timestamp. Historical snapshots are validated against the same reference graph and definitions during import. Existing observations without this extension remain valid. Deleted records and their histories are included in backups. Prior v1 builds preserve unknown extensions but do not display or maintain this history; do not use an older build to edit these records.

Photo originals are immutable `photoAssets` records containing UUID `id`, `profileId`, `createdAt` (attachment time, not capture time), `mediaType`, pixel `width`/`height`, and a base64 `dataUrl`. Photo references live in `extensions["breadcrumb.photos"] = {version: 1, items: [{assetId, caption, marks}]}`. Marks contain `tool` (`pen`, `arrow`, or `circle`), an allowed `color`, and normalized `points` with x/y in [0,1]. Shapes have two points; freehand has 2–500. Captions allow 1,000 characters, attachments six per entry, and marks 100 per photo. Current and historical references must belong to the observation's profile. Earlier annotation sets and removed attachments remain in edit history; original bytes are stored once per asset ID.

Imports and exports support up to 100 MiB in this prototype. Photo data is capped at 48 MiB of base64 strings across the backup. Individual photos are capped at 8 MiB decoded / 40 megapixels. Validation checks raster MIME, base64/signatures, dimensions, annotations, and references; it is not a full image decoder. A browser unable to render an imported original shows an error while retaining its bytes. Files are parsed and validated locally. Invalid references, cross-profile references, mismatched fields, conflicting IDs, and unsupported versions fail without changing saved data. Identical backups can be restored repeatedly without duplicates.

Exports are unencrypted readable JSON. The app can initiate a download but cannot confirm the user's filesystem saved it; verify it in Downloads. CSV and clinician reports are later milestones.
