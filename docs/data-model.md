# Domain model

`src/domain/types.ts` is the executable definition: strict Zod schemas and inferred TypeScript types for EventType, Observation, MedicationSchedule, Episode, Profile, Preferences, Tag, RecordedTime, and Backup. `src/domain/validation.ts` validates the whole reference graph before writes/imports.

`src/domain/photos.ts` defines PhotoAsset, Attachment, and PhotoMark. Assets are immutable, profile-owned original raster bytes in the v2 database store. Attachments and their captions/normalized annotation points live in the versioned `breadcrumb.photos` observation extension. Editing this extension snapshots its earlier state with the observation. Photo assets and entry changes commit atomically; validation rejects missing/cross-profile references and attempts to overwrite an original. Removing an attachment retains its original for historical references. Observation time and attachment time remain independent; EXIF time is never inferred as observation time.

- EventType and MedicationSchedule use compound `[id, revision]` keys. Historical definitions remain available. Changes to meaning require a new revision, not rewriting an existing definition.
- Observation stores occurrence time independently of creation time. Approximate time is a bounded uncertainty window, not a duration. Point, ongoing, and ended are explicit span states.
- Observation corrections preserve ID, creation time, historical EventType reference, duration, tags, source, and unrelated extensions. Editable fields are start time, notes, values, and medication action/dose; duration/type/tag editing is not yet exposed. Unchanged timestamps retain original seconds and time zone. Each correction, soft deletion, and restoration appends a prior snapshot to the versioned `breadcrumb.observation-history` extension. Stale writes compare the full canonical record, so newer work cannot be overwritten.
- PRN is `rule.kind = 'as-needed'`; no schedule record means unconfigured. Neither implies an expected dose. Only explicit medication observations record taken/skipped actions. Plans never generate observations. Occurrence generation and matching records to scheduled times remain deferred; UI dose records have `occurrence: null`.
- A schedule revision ends at the earlier of its explicit `effectiveUntil` and its next revision's `effectiveFrom`. Editing or stopping a plan appends a revision without mutating past records. Separate schedule IDs allow multiple concurrent plans for one medication.
- Stable tag IDs prevent renames from breaking references. The future tag editor must trim labels and match case-insensitively; no tag editor is shipped in this slice.
- Episode links express user association, not medical causation. Episodes support exact/approximate start and optional end, editable names/notes, and Look Back around their start. An absent end does not imply symptoms continued. Window adjustments in Look Back are temporary view settings.
- Profile IDs scope records. Preferences belong to a profile. The active profile ID is device metadata, not portable profile data.
- Journal creation atomically saves a new profile, preferences, independent starter definitions, and active-profile choice. Settings edits check profile and preference timestamps to reject stale changes. Only name, favorite order, and default Look Back window are exposed in this release; other stored preferences and extensions remain intact. Switching clears observation/episode selections and open editors. Profile separation is organizational, not authentication.
- Archived/deleted definitions remain valid historical references. There is no deletion UI in this slice.
- Unknown namespaced JSON extension data survives JSON round trips. Unknown core properties are rejected instead of silently discarded.

The UI writes point observations with optional notes and user-defined fields. Make it yours creates and revises event definitions without overwriting historical revisions. Editors and logging forms reject stale revisions to prevent concurrent changes from reinterpreting values. It can display imported explicit duration states. Medication logging requires an explicit taken/skipped choice; taken amount is optional and never prefilled from a plan. Episodes reject stale edits to protect changes made in another tab.

The default profile caption is My journal. Old starter profiles named My space use that caption through a presentation alias; their records are not rewritten, preserving compatibility with existing backups.
